# Mechanica Launcher

Лаунчер Minecraft для Windows x64. Интерфейс на Nitidus / ORDO и .NET 10, игровое ядро на .NET 9. Поддержка отдельных версий игры и загрузчиков требует проверки реальным запуском: проект пока проходит стабилизацию.

План итераций и критерии релиза: [PLAN.md](PLAN.md). Фактические запуски и способ повторить их: [COMPATIBILITY.md](COMPATIBILITY.md).

## Разработка

Портативный ZIP для передачи на другой компьютер: `./scripts/Build-Portable.ps1`. По умолчанию архив появится на рабочем столе. Он включает .NET и `portable.flag`; настройки и сборки создаются в `data` рядом с EXE. Явный `MECHANICA_DATA_DIR` имеет приоритет. Архив собирается в новой папке и не содержит пользовательские данные.

Обнаружение и очистка TLauncher, исключения для TLegacy и формат резервных копий: [TLAUNCHER_CLEANUP.md](TLAUNCHER_CLEANUP.md).

Рабочая конфигурация: Windows x64, .NET SDK 10 и runtime .NET 9 для тестов ядра. Nitidus и компилятор ORDO закреплены в локальном NuGet-feed [vendor/nitidus](vendor/nitidus/README.md). Соседний checkout CSharpUiRenderer для обычной сборки не нужен.

```powershell
dotnet restore MechanicaLauncher.sln -p:Platform=x64 --locked-mode
dotnet build MechanicaLauncher.sln -c Debug -p:Platform=x64 --no-restore
dotnet run --project tests/MechanicaLauncher.Core.Tests -c Release
dotnet run --project tests/MechanicaLauncher.Desktop.Tests -c Release
dotnet publish src/MechanicaLauncher/MechanicaLauncher.csproj -c Release -p:Platform=x64 -p:SelfContained=true -p:PublishTrimmed=false -p:RestoreLockedMode=true -r win-x64 --output out/nitidus-portable
./scripts/Test-DesktopPortable.ps1
```

Проверки — отдельное консольное приложение без дополнительных тестовых пакетов. Ненулевой код завершения означает ошибку. HTTP-ответы и процесс установщика имитируются локально; Minecraft, Java и моды не скачиваются. Настройки пользователя и существующие сборки не используются.

Если локальный SDK падает в обработчике workloads, для сборки можно добавить `-p:MSBuildEnableWorkloadResolver=false`. Это обход проблемы окружения, а не обязательная настройка проекта.

## Интерфейс Nitidus / ORDO

Активный UI находится в `src/MechanicaLauncher/Desktop`: ORDO компилирует разметку в C#, Nitidus рисует её через Direct3D / DirectWrite. Старые XAML-файлы сохранены как исходники предыдущей реализации и исключены из сборки. Windows App SDK больше не требуется. Системные диалоги выбора файла и окно авторизации Microsoft используют WinForms; WebView2 нужен только для входа Microsoft.

Две темы, адаптивная компоновка от 840×620, русская и английская локализация. Главная показывает обложку выбранной сборки и панель запуска; без обложки используется компактный вид. При первом запуске доступны создание сборки, импорт и поиск модпака.

Переходы через `Nitidus.Motion` сопровождают действие пользователя или изменение данных: появление страницы и диалога, переключение раздела, нажатие кнопки и обновление прогресса. Прокрутка длинного названия или статуса на главной сохраняет доступ к панели запуска и журналу. Колесо использует обычную прокрутку Nitidus без дополнительной инерции и эффектов на строках.

Главная и списки в покое не требуют кадров анимации. Индикатор работы отражает состояние операции без постоянной пульсации. Переключатель «Плавные переходы» и системная настройка Windows отключают эффекты, включая уже запущенные. Описание проекта показывает текст, заголовки, изображения и HTTPS-ссылки средствами Nitidus; сложная HTML-вёрстка сайта не воспроизводится.

Редактор скина поддерживает карандаш, ластик, заливку, пипетку, отмену последних действий, PNG 64×64 / 64×32 и загрузку текущего скина. Неудачная загрузка изображения оставляет страницу рабочей.

## Текущий запуск и восстановление

- Play проверяет клиент, библиотеки и ресурсы. Для файлов с хешем проверяется содержимое, для остальных — наличие и ненулевой размер.
- Незавершённые скачивания не заменяют конечный файл. Временные сетевые ошибки повторяются не более трёх попыток; HTTP 404 сразу считается ошибкой.
- Автовыбор Java использует major-версию из метаданных игры. Для ручного выбора требуется такая же версия; неизвестная или неподходящая Java даёт ошибку до запуска.
- Архитектура Java проверяется по EXE. Offline UUID вычисляется по имени игрока; передаётся конфигурация логирования Mojang.
- Установка загрузчика завершается записью профиля и `.complete`. Сборки от предыдущей реализации один раз переустанавливают загрузчик при Play.
- Forge/NeoForge запускают процессоры установщика. Старый формат установщика без `version.json` пока не поддержан.
- Диагностика отсутствующих служебных файлов предлагает восстановление. Миры остаются в `saves`.
- Настройки и профили сохраняются атомарно; предыдущая версия находится в `.bak` и используется при повреждении основного JSON.
- Во время подготовки кнопка Play отменяет операцию. Закрытие окна при активной игре или загрузке скрывает лаунчер в трей. Пункт «Выход» отменяет загрузки после подтверждения и оставляет запущенную игру открытой; отменённую загрузку можно повторить.
- Импорт `.mrpack` проверяет пути, SHA1/SHA512 и client/server окружение. Новая сборка появляется после завершения импорта; `client-overrides` имеют приоритет. При добавлении в существующую сборку её конфигурация и миры сохраняются.
- Обязательные зависимости модов разрешаются рекурсивно, включая закреплённый `version_id`. Ошибка скачивания прерывает установку до публикации набора файлов.

## Каталог контента

- Каталог и установленное разделены на вкладки. Сборка выбирается прямо на странице; поиск, категории, сортировка и фильтр совместимости сохраняются при возврате из проекта.
- Фильтр «Только Minecraft …» включён по умолчанию для модов, модпаков, шейдеров, ресурспаков и датапаков и использует версию выбранной сборки. Для модов учитывается также её загрузчик. У модпака фильтр переносится в список файлов для установки; загрузчик берётся из самого модпака. Снятие галочки открывает весь каталог и все версии модпаков; без выбранной сборки каталог тоже не ограничивается версией.
- Кнопка «Подробнее» открывает описание, галерею скриншотов и список версий. По умолчанию выбирается последняя стабильная совместимая версия; предварительные версии отмечены.
- Моды устанавливаются в `mods`, шейдеры — в `shaderpacks`, ресурспаки — в `resourcepacks`. Для датапака нужно выбрать существующий мир: файлы попадут в его `datapacks`.
- Модпак из каталога создаёт отдельную сборку с Minecraft и загрузчиком из манифеста. Игра и Java подготавливаются при первом запуске.
- Установку можно отменить. Файлы проверяются по хешам перед публикацией; установленный файл можно проверить повторно. Другая найденная версия проекта требует сначала удалить прежнюю через вкладку «Установлено».
- В установленном доступны включение, отключение и удаление после подтверждения. Шейдеры требуют Iris/OptiFine, а ресурспаки после скачивания включаются в настройках игры.

Данные приложения: `%APPDATA%\MechanicaLauncher`. Журналы сборки: `instances\<id>\.minecraft\logs\launcher-latest.log`, `forge-installer.log`, `neoforge-installer.log`.

## Настройки сборки, загрузки и серверы

- «Настройки сборки» на главной и шестерёнка в списке открывают параметры игры: память, размер окна, переход к модам и название. Java и JVM находятся в свёрнутых дополнительных параметрах. Сохранение проверяет введённые значения и блокируется во время запуска/игры; переключение внутренних вкладок сохраняет черновик.
- Совместимость, скриншоты, история вылетов и необязательное оформление доступны отдельными вкладками.
- Совместимость проверяет включённые JAR, повреждённые архивы, дубли, загрузчик и версии Minecraft по Modrinth. Для Fabric читаются зависимости, `provides`, вложенные JAR, числовые диапазоны версий и `breaks`. Нераспознанные файлы отмечаются; проверка не обещает обнаружить все игровые конфликты. Снимки и prerelease-диапазоны Fabric не интерпретируются как обычные числовые версии.
- Перед запуском выполняется быстрая локальная проверка с кешем каталога. Найденные ошибки можно открыть в настройках сборки или явно продолжить запуск. Полная проверка по кнопке передаёт Modrinth только хеши файлов.
- «Загрузки» в боковом меню показывает очередь установок каталога и `.mrpack`, подготовку игры, переданные байты, скорость и проверенные файлы. Можно отменить операцию и повторить неудачную целиком; после перехода на другой экран она продолжается. При закрытии приложения незавершённая работа отменяется. История очереди хранится только в текущем сеансе.
- Неожиданное завершение игры сохраняет до 20 отчётов на сборку: вероятная причина, действие и ограниченный хвост лога. Остановка кнопкой лаунчера не считается вылетом. Из отчёта исключаются известные токены текущей сессии и распространённые поля секретов; отчёты никуда автоматически не отправляются.
- Галерея читает локальную папку `screenshots`, показывает новые снимки первыми и позволяет листать, открыть оригинал или сохранить копию. Миниатюры загружаются порциями.
- Оформление: собственная иконка, PNG/JPEG-обложка до 20 МБ, цвет акцента, сброс и компактный список сборок. Иконка и оформление применяются кнопкой сохранения. Обложка отображается также на главной и сохраняется при дублировании сборки.
- «Любимые серверы» хранит адрес и выбранную сборку; доступны изменение, удаление из избранного, подключение, версия, MOTD, игроки и задержка. Статус Java-сервера проверяется только по кнопке, с таймаутом и ограничением размера ответа. Для проверки статуса используется прямой TCP-хост/порт, без DNS SRV и старого протокола до Minecraft 1.7.

Компонентная проверка Nitidus: `dotnet run --project tests/MechanicaLauncher.Desktop.Tests -c Release`. Прежний `./tests/MechanicaLauncher.Ui.Smoke/Run.ps1` вызывает этот же прогон. HeadlessHost использует настоящий рендерер с программным D3D: проверяются клики, ввод, размеры 840/1000/1180, обе темы, контраст и английский экран при DPI 150%. PNG-кадры и изолированные данные сохраняются в `tests/out/nitidus-ui-tests-*`.

Проверки каталога используют имитацию HTTP вместо Modrinth: фильтры пяти типов, смену сборки, список версий модпака, стабильный релиз, отключение фильтра, устаревшие ответы и отсутствие подходящего файла. Внешние запросы и установки при этом не выполняются.

Для отдельного каталога данных задайте переменную окружения `MECHANICA_DATA_DIR` с абсолютным путём перед запуском процесса. Настройки, сборки, кеш и межпроцессные сообщения будут изолированы; такой запуск не перерегистрирует системные ассоциации. Необработанные ошибки приложения пишутся в `logs/launcher-errors.log` внутри каталога данных.

## Discord Rich Presence

В «Настройки → Discord» доступны предпросмотр, состояние подключения и переподключение. Включение, выключение, язык и приватность применяются без перезапуска игры.

- Статус показывает подготовку, запуск, меню или игру, сборку, Minecraft, загрузчик и число включённых файлов модов. Время считается от запуска процесса игры и сохраняется при переподключении Discord.
- При нескольких играх показывается последняя запущенная; после её закрытия возвращается предыдущая. Подготовка второй сборки не перебивает уже работающую игру.
- После завершения игры очищаются её метаданные и таймер. При выключении Rich Presence лаунчер ждёт подтверждения очистки от Discord перед закрытием соединения.
- Адрес сервера скрывается во всех полях карточки при выключенном переключателе. Достижения показываются только для собственного ника и исчезают через 30 секунд. Обновления журнала объединяются с интервалом 5 секунд.
- Используется существующее Discord-приложение Mechanica и публичная PNG-иконка из ресурсов Mojang с фиксированной версией URL. Несуществующие ключи изображений больше не отправляются; кнопка открывает HTTPS-страницу лаунчера.

Нужно приложение Discord на компьютере с разрешённым показом активности. Мир, сервер, режим и измерение определяются по журналу Minecraft; не каждая версия или сборка сообщает все переходы. Подготовка/сохранение измерений и режим мира по умолчанию не считаются сведениями о текущем игроке. Если стартовые сообщения не распознаны, через 30 секунд показывается нейтральное «Minecraft запущен». Точное отслеживание всех игровых переходов потребует интеграции внутри игры.

Локальные тесты используют имитацию Discord IPC. Отдельная проверка с настоящим Discord временно публикует тестовые статусы Mechanica и очищает их после проверки:

    dotnet run --project tests/MechanicaLauncher.Core.Tests -c Release -- --discord-smoke

## Вход Microsoft

Вход и обновление учётной записи доступны на странице «Аккаунт». Кнопка смены аккаунта Microsoft сохраняет текущий профиль до успешного завершения нового входа. Закрытие формы отменяет интерактивный вход; истёкшая сессия, отсутствие Xbox/Java-профиля и отказ регистрации приложения имеют отдельные сообщения.

Для новых входов и обновления старых сессий по умолчанию используется прежний legacy Client ID. Собственное приложение Mechanica пока не зарегистрировано. Если задан `MECHANICA_MICROSOFT_CLIENT_ID` или ID встроен в сборку, новый вход использует его; существующая сессия обновляется с сохранённым ID.

Параметры регистрации и сборки собраны в [MICROSOFT_AUTH.md](MICROSOFT_AUTH.md). Для разработки доступна переменная `MECHANICA_MICROSOFT_CLIENT_ID`, для распространяемой сборки — `-p:MicrosoftClientId=<Application ID>`. ID, с которым выполнен вход, сохраняется вместе с сессией; обновление использует тот же клиент. Client secret не требуется. Своя регистрация, допуск к Minecraft Services и успешный вход с реальным аккаунтом остаются пунктами приёмки перед публикацией.

## Граница проверки

После переноса проходят тесты ядра и компонентные проверки Nitidus, включая жизненный цикл дочернего процесса, отмену, повтор загрузки и сохранение отчёта о вылете. Проверены обе темы, компоновка при DPI 100/150/200%, клавиатурный фокус и длинные формы. Portable проверяется отдельным запуском настоящего окна, передачей команды вторым процессом и штатным закрытием. Игровой процесс в новых UI-тестах имитируется отдельным EXE; это не проверка настоящего Minecraft.

Предыдущие реальные запуски девяти сочетаний Minecraft/загрузчиков, обновление Microsoft-сессии, живой каталог и Discord зафиксированы в [COMPATIBILITY.md](COMPATIBILITY.md) и относятся к предыдущему интерфейсу. Полный новый вход, игровые миры/серверы, большие реальные модпаки, чистая Windows и установщик остаются этапами [плана](PLAN.md). Ручная проверка нового desktop UI и доступности ещё нужна: текущий Nitidus не предоставляет UI Automation / screen reader integration. Сборки ARM64/x86 не выпускаются.
