# План доведения Mechanica Launcher до релиза

## Что считаем готовым продуктом

Первый релиз — Windows 10/11 x64. Пользователь может создать или импортировать сборку, установить игру, запустить её повторно, получить понятную причину ошибки и восстановить служебные файлы без потери миров и настроек. Поддержку конкретной пары Minecraft/загрузчик подтверждаем запуском игры; успешной компиляции недостаточно.

Работа идёт итерациями. Каждая заканчивается проверяемым результатом, регрессионными проверками и списком оставшихся ограничений. До прохождения релизной матрицы продукт не считается готовым.

## Текущий результат — 22.09.2026

### Nitidus / ORDO

Основные страницы, диалоги, каталог, загрузки, настройки сборок, скриншоты, вылеты, серверы, аккаунт и редактор скина перенесены на ORDO. Nitidus подключён через закреплённые локальные NuGet-пакеты. Добавлены две темы, адаптивность и отключаемые анимации. Прежние XAML-исходники исключены из сборки и сохранены для сравнения.

Проверки миграции: 104 теста ядра; текущий UI проходит 1482 компонентные проверки, включая процессы и переходы. После настройки интенсивности Nitidus.Motion используется для короткого появления экранов и диалогов, цветового отклика кнопок и обновления прогресса. Постоянное парение, параллакс, наклон, каскад карточек и эффекты скролла убраны. Проверены добавления в список на ходу до 11 202 элементов, переиспользование строк, сохранение позиции чтения и немедленные клики по новым элементам. Главная и списки в покое не требуют кадров анимации. Следующая приёмка: новый Microsoft-вход, полный игровой цикл в новом UI, большие модпаки, чистая Windows и установщик. Ограничения текущего Nitidus: нет UI Automation, нет SVG, поддерживается только собранный x64 backend.

### Предыдущие итерации

- Итерация 1: 101 локальная проверка проходит. Проверки охватывают целостность загрузок, OAuth, маршруты установки контента, HTML описаний, совместимость, очередь, вылеты, медиа, серверный протокол и Discord RPC.
- Итерация 2: 9 сочетаний игры и загрузчиков прошли настоящую установку, два запуска и штатное завершение. Точные версии и границы: [COMPATIBILITY.md](COMPATIBILITY.md).
- Итерация 3: исправлены импорт/экспорт `.mrpack`, SHA1/SHA512, пути, приоритет client-overrides, скрытие незавершённого импорта и рекурсивные зависимости модов. Сохранность миров и отказ обязательного скачивания проверены локально. Большой реальный модпак остаётся отдельным сценарием.
- Итерация 4: визуально проверены создание сборки, отмена подготовки, ошибка сети и повтор из кеша, сохранение языка/темы после перезапуска, запуск Minecraft 26.3, скрытие и возврат окна. Исправлены сброс настроек при открытии страницы, закрытие пустой формы, зависание списка версий при ошибке сети и читаемость подписей светлой темы. Полная локализация, DPI и остальные сценарии остаются в приёмке.
- Дополнение к итерации 4: исправлены контраст модов/сборок, фильтры и акцентные кнопки, компоновка при малой ширине. Устранён сбой выгрузки микроанимаций; поиск отменяет устаревшие запросы.
- Каталог контента: добавлены отдельная страница проекта, Markdown-описание, галерея, выбор версии/сборки/мира, категории по типу контента и отмена установки. Исправлены установка ZIP-паков и создание отдельной сборки для модпака. Живой API всех пяти типов и реальная загрузка ресурспака проверены; визуальная приёмка нового экрана остаётся открыта из-за недоступного native computer-use.
- Итерация 5: portable собран. OAuth получил PKCE/state, отмену, обновление с привязкой к client ID и сообщения ошибок Xbox/Minecraft. Обе цепочки входа покрыты локальными проверками. Настоящая сохранённая сессия успешно обновлена через Microsoft/Xbox/XSTS/Minecraft, UUID совпал, новый токен сохранён и принят сервисом. Чистая Windows, полный новый вход с вводом учётных данных и установщик пока не проверены; Inno Setup отсутствует на текущей машине. Релиз не опубликован.
- Настройка Microsoft: по умолчанию новые входы используют прежний legacy Client ID. Свой ID можно задать через окружение или встроить в сборку; обновление сессии использует сохранённый ID. Собственное приложение ещё не создано. Для перехода на него подготовлена [инструкция регистрации](MICROSOFT_AUTH.md); выпуск по тегу в CI пока требует собственного ID.
- Требования заявки Minecraft проверены по официальной форме: явного порога популярности нет, нужны описание проекта и обоснование доступа. До подачи необходимо проверить текущий offline-режим на соответствие условиям авторизации и лицензии; одобрение не гарантировано.

## Шесть пользовательских функций — реализованы

Дополнение от 22.09.2026 выполнено тремя этапами:

1. Совместимость и объяснение вылетов: локальная проверка перед Play, полная проверка по хешам, сохранённые отчёты с причиной и действием.
2. Центр загрузок: очередь каталога/импорта, подготовка игры, отмена, безопасный повтор, работа после перехода между страницами.
3. Управление сборкой: локальная галерея, обложки и акценты, компактные карточки, любимые серверы с привязкой к сборке.

Ограничения этой итерации: очередь не восстанавливается после перезапуска; все runtime-конфликты модов заранее определить нельзя; статус серверов не использует SRV. Полная ручная приёмка новых диалогов и клавиатурных переходов остаётся открыта: native computer-use недоступен.

## 1. Целостность установки и повторный запуск — реализована

- Проверять клиент, библиотеки и ресурсы при каждом Play; докачивать отсутствующие и повреждённые файлы.
- Загружать во временный файл, проверять размер/хеш, затем заменять конечный файл. Повторять только временные сетевые ошибки, ограничивать ожидание.
- Сохранять профиль загрузчика после успешной установки. Прерванная установка должна продолжаться при следующем Play.
- Выбирать Java по версии из метаданных игры. Ошибочный ручной путь должен давать объяснение.
- Одинаково применять правила ОС/архитектуры к библиотекам и аргументам; поддержать старый формат natives.
- Исключить повторную подготовку запуска при обновлении страницы и гонки между завершением процессов.
- Диагностика восстанавливает файлы, сохраняя миры, моды и настройки.
- Добавить локальные проверки с искусственными сетевыми сбоями, без скачивания Minecraft и зависимости от внешних сервисов.

Приёмка: оборванная загрузка, неверный хеш, отсутствующая библиотека, повторная установка и неверная Java воспроизводятся проверками; Debug/Release x64 собираются.

Результат: добавлены 27 локальных регрессионных сценариев, проверки включены в CI. Сохраняются журналы подготовки и установщиков, при отмене дочерний процесс завершается. Исправлен выбор сборки при deep link и возврат окна после быстрого завершения игры.

Также выполнена часть следующих итераций: подключены процессоры Forge/NeoForge, разбираются JVM-аргументы в кавычках, кешируются метаданные, сохраняются резервные копии настроек/профилей, закреплены NuGet-зависимости. Сетевой сбой не стирает refresh token.

Граница приёмки: сценарии установки проверены на локальных HTTP-ответах и тестовом дочернем процессе. Реальные Minecraft/Forge/NeoForge, Microsoft-вход и WinUI вручную ещё не проверены.

Проверено 15.09.2026:

| Проверка | Результат |
| --- | --- |
| Restore в locked mode | Прошёл |
| Локальные регрессионные сценарии | 27 прошли, 0 ошибок |
| Debug x64 | Собран |
| Release x64, self-contained portable | Собран в `out/stability-portable` |

Остаются предупреждения CA1416 об использовании Windows API в Core; проверяемая платформа этого этапа — Windows x64. Portable ещё не проходил ручную проверку запуска окна.

## 2. Совместимость игры и загрузчиков — проверена указанная матрица

- Forge/NeoForge: выполнение процессоров установщика, проверка выходных артефактов, ограничение времени, сохранение журнала.
- Проверить Vanilla 1.12.2, 1.16.5, 1.20.1, 1.21.1 и актуальный стабильный релиз из Mojang manifest.
- Проверить Fabric, Quilt, Forge, NeoForge только на существующих совместимых версиях. Зафиксировать точные версии в матрице.
- Проверять архитектуру выбранной JVM; не смешивать x86, x64 и ARM64 natives.
- Проверить наследование профилей, порядок библиотек и аргументы JVM с пробелами/кавычками.

Приёмка: для каждой заявленной пары есть холодная установка, повторный запуск, выход без ошибки и журнал. Неподдержанные сочетания объясняются до установки.

## 3. Сборки и пользовательские данные

- Импорт `.mrpack`: проверка путей, хешей, client/server окружения и обязательных зависимостей; корректный приоритет client-overrides.
- Незавершённый импорт не показывать как готовую сборку; дать повторить импорт.
- Установка модов должна учитывать закреплённую версию зависимости и её зависимости; ошибка обязательного мода не скрывается.
- Атомарно сохранять настройки и профили, восстанавливать резервную копию при повреждении JSON.
- Не изменять моды и не удалять сборку во время игры/установки. Удаление данных — отдельное явное действие.

Приёмка: импорт/экспорт с повторным запуском, обрыв импорта, повреждённый архив/JSON и сохранность существующего мира проверены.

## 4. Предсказуемый интерфейс и диагностика

Проверено 16.09.2026 через Windows Computer Use в отдельных каталогах `out/ui-review-*`:

- Пустое название блокирует создание; после ввода имени сборка создаётся и сохраняется.
- Ошибка загрузки версий видна в форме. «Повторить» использует доступный кеш; введённое название сохраняется.
- Первый вход в настройки больше не перезаписывает язык и тему значениями XAML. Тема хранится как `Dark`/`Light`/`System`, независимо от перевода подписи.
- Русский язык и светлая тема сохраняются после перезапуска и повторного входа в настройки. Навигация локализована; второстепенный текст учитывает тему.
- Отмена подготовки возвращает кнопку запуска. Minecraft 26.3 дважды запущен из интерфейса до главного меню и закрыт с кодом 0; лаунчер скрывается и возвращается.
- CI явно устанавливает .NET 9 для проекта регрессионных проверок и .NET 10 для сборки.
- Главный экран получил приглушённую светлую палитру и адаптивный блок запуска. Убраны случайный слоган, пульсация и постоянная плашка готовности; проверены обе темы, длинные названия, компактное окно, переход по карточке с клавиатуры и запуск/остановка игры.

- Единое состояние операции: проверка → загрузка → установка → запуск → работает → завершено/ошибка/отменено.
- Отмена длительной операции с корректным завершением дочерних процессов; повтор доступен сразу после окончания.
- Журнал включает подготовку и запуск, сохраняет последний stderr; сообщение указывает этап и действие для восстановления.
- Отделить отсутствие сети/недоступность сервиса от истёкшей авторизации; сетевой сбой не стирает refresh token.
- Кешировать метаданные для повторного запуска установленной игры без сети; поведение Microsoft-сессии определить явно.
- Проверить запуск из deep link, выбор нужной сборки, скрытие/возврат окна, отсутствие повторных диалогов.
- Завершить русскую локализацию основных ошибок, пустых состояний и прогресса.

Приёмка: все переходы проходят ручную проверку; нет бесконечной загрузки, ложного успеха или потери причины ошибки.

## 5. Релиз и сопровождение

- Зафиксировать версии зависимостей; запускать регрессионные проверки в CI перед публикацией артефактов.
- Проверить portable и установщик на чистой Windows без SDK: первый запуск, обновление, повторный запуск.
- Проверить Microsoft-вход/обновление сессии и конфигурацию собственного OAuth-клиента; до этого вход не считать релизно проверенным.
- Обновление приложения сохраняет сборки и настройки; проверить отказ загрузки/установки обновления.
- Проверить DPI 100/150/200%, клавиатуру, длинные пути, кириллицу, отсутствие прав записи и нехватку диска.
- Подготовить README, краткую инструкцию восстановления и известные ограничения; версия релиза определяется проверенным набором возможностей.

Приёмка: все блокирующие пункты закрыты, матрица заполнена фактическими результатами, установщик и portable проверены. Публикация выполняется отдельной командой владельца.

## Исходные результаты аудита

- Сборка Debug x64 проходит после восстановления NuGet. Тестового проекта не было.
- Профили загрузчиков записывались до загрузки зависимостей; следующий Play считал их установленными.
- Наличие client.jar отключало проверку остальных файлов Vanilla.
- Forge скачивал профиль и библиотеки, но не выполнял процессоры установщика.
- Java выбиралась как самая новая найденная; Java `1.8.*` определялась как версия 1.
- Ошибки загрузки части модов/сборок подавлялись. Настройки и профили записывались напрямую.
- Диагностика отсутствующего профиля загрузчика предлагала удалить всю сборку.

## Источники для проверки форматов

- [Mojang version manifest](https://piston-meta.mojang.com/mc/game/version_manifest_v2.json): конкретные профили содержат Java, downloads, rules и natives.
- [Исходники Forge Installer 2.0](https://github.com/MinecraftForge/Installer/tree/2.0): поддерживают установку клиента через командную строку; старые форматы требуют отдельной поддержки.
- [Документация NeoForge](https://docs.neoforged.net/docs/gettingstarted/): требования меняются между версиями Minecraft.
